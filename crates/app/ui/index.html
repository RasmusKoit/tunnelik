        How this works

        Programs and domains are Windows' own VPN triggers, so they need the switch above. Windows watches one tunnel at a time and keeps that tunnel's profile system-wide. Names under a domain resolve through the tunnel's DNS. After you disconnect the tunnel yourself, Windows waits for the next network change or sign-in before starting it again. The request that starts the tunnel runs before it is up, so it may fail once; a toast says when the tunnel is up. Changing programs or domains rebuilds the tunnel's VPN connection, reconnecting it afterwards if it was up. A browser with its own secure DNS never reaches the Windows resolver and so never triggers anything.

        Ranges are watched by Tunnelik itself and need nothing turned on. Only TCP connections are seen; ping and UDP leave no trace. The attempt that starts the tunnel fails, the program's next try goes through. After you disconnect the tunnel yourself it stays down for ten minutes.
